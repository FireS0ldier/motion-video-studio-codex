# AGENTS.md — working in Motion Video Studio

You are working in a **motion-as-code video studio**. Videos are TypeScript projects in `projects/<id>/`, rendered by a stable engine (`engine/`) through a CLI (`npx mvs …`). This file tells you how to make a new, professional product/app/marketing video **without modifying the engine**. This is the **Codex edition** of the studio: Codex loads this file automatically (other agents that read `AGENTS.md` can use it too).

Read this file fully once. Then use the docs in `docs/` as reference when you need details. Project skills (Agent Skills format) are in `.agents/skills/`: `create-video`, `add-scene`, `review-video`. Codex settings for this repository (network for the sandbox, model): `.codex/config.toml`; sandbox, caches, Codex Cloud and model choice: `docs/codex.md`.

---

## 1. Mental model (60 seconds)

- A video = **script** (`script.md`, the voiceover words) + **timeline** (`timeline.ts`, which scene plays when) + **scenes** (`scenes/*.ts`, what is drawn) + **brand** (`brand.ts`) + **assets** (`assets/`) + **audio** (voiceover, music, SFX cues).
- A scene's `render(f, g)` is a **pure function of time**. `f` = frame context (time, progress, voiceover lookups), `g` = graphics API. The engine calls it for every frame (and several sub-frames for motion blur), in any order, in parallel workers.
- Timing comes from the voiceover: `data/timing.json` maps every script word to seconds. Scenes look words up **by content** (`f.in('faster')`, `section('intro')`, `cut('Meet Orbit')`), so a new voiceover only needs `npx mvs align`.
- Preview = export. What you see at `npx mvs dev` is exactly what `npx mvs render` produces.

## 3. Create a new video — the workflow

Follow these steps in order. Commands are run from the repo root.

1. **Check the machine:** `npx mvs doctor` (first time: `npm install && npm run setup`).
2. **Scaffold:** `npx mvs new <id> --title "Product Launch" [--format landscape|vertical|square] [--language de]` (German: starter with German script, texts and voice).
3. **Collect inputs** from the user (ask if missing): product name + one-line pitch, target audience, key features (3–5), proof points/numbers, call to action + URL, brand colors/fonts/logo, screenshots/recordings, voiceover file (or permission to generate one), desired length (30–90 s is typical) and format.
4. **Write `script.md`.** Sections (`## Hook {#hook}`) become scene boundaries. ~150 words per minute. One idea per sentence. Use `{display|spoken}` for numbers/URLs/acronyms (`{40%|forty percent}`, `{orbit.dev|orbit dot dev}`). See `docs/script-format.md`.
5. **Brand:** edit `brand.ts` (colors, `logo: { mark: 'assets/brand/logo.svg' }`, motion preset `smooth|snappy|bouncy|cinematic`). Fonts: bundled Inter/JetBrains Mono/Instrument Serif, or add woff2 files (see `docs/scene-api.md#fonts`).
6. **Assets:** put files into `projects/<id>/assets/`: `screens/` (PNG, 2× resolution ideal), `recordings/` (MP4/MOV), `brand/` (SVG logo), `audio/voiceover.wav` (auto-detected), `images/`. No real screenshots? Build an HTML mock and capture it (pattern: `projects/orbit-launch/assets-src/make-assets.ts`) or draw UI with the kit.
7. **Voiceover:** user file → `assets/audio/voiceover.wav`. Or `npx mvs voice <id>` (local TTS: Kokoro for English and 7 more languages; Piper for German (`language: de`), which also writes `data/timing.json` so step 8's `align` is not needed). If none yet: skip; timing is estimated from the script.
8. **Timing:** `npx mvs align <id>` (auto: TTS timing after a Piper voice, CTC for English; `--engine whisperx --language de` for recorded non-English voices; `--estimate` without audio). Then `npx mvs analyze <id>`.
9. **Scenes + timeline:** start from the template's `scenes/index.ts`. Use templates (`templates.showcase`, `kinetic`, `features`, `stats`, `code`, `phoneShowcase`, `cta`, …) and write custom scenes for the special moments. Anchor scene starts with `section('id')` / `cut('phrase')`. Choose transitions with intent (see §7).
10. **Preview:** `npx mvs dev <id>` (if you cannot see a browser, use stills and the review pack instead).
11. **Validate:** `npx mvs check <id>` → fix **every** error and warning you can.
12. **Look at it:** `npx mvs review <id>` → open `out/<id>/review/contact.png` and the per-scene/per-transition PNGs with `view_image`. The contact sheet is wide and may be shown downscaled: judge details on the per-scene PNGs. Judge them against the quality bar (§7). Iterate on scenes. Use `npx mvs still <id> --t 12.5` for single moments. If you cannot view images, say so in your report instead of claiming a visual review.
13. **Draft:** `npx mvs render <id> --draft` → watch/inspect `out/<id>/<id>-draft.mp4` (extract frames with ffmpeg if you cannot play video).
14. **Final:** `npx mvs render <id>` → `out/<id>/<id>.mp4` (+ `.render.json` report). **Ask before 4K (`--uhd`)** — it is ~4× slower.

```
npx mvs doctor                         environment check

npx mvs sfx --list                     sound library

npm run test:e2e                       render tests (slow)
```

## 5. Writing scenes

```ts
import { defineScene, kit, templates as T } from '@mvs/engine'

export default defineScene({
  name: 'features',
  render(f, g) {
    kit.background(g, { kind: 'mesh' })          // always paint a background first
    g.camera(kit.drift(f))                        // keep shots alive: slow push + float
    const { s } = kit.responsive(f.stage)         // size multiplier for any format
    g.text('Every metric. **Live.**', {
      x: f.stage.cx, y: f.stage.cy - 200 * s, style: 'h1', size: 96 * s,
      anim: { preset: 'mask', sync: 'voice' },     // each word appears when spoken
    })
    const p = f.in('dashboard', 0.7)              // 0..1 when "dashboard" is spoken
    g.layer({ w: 1200, h: 740, y: f.stage.cy + 120 * s, rotateY: -16 * (1 - p), opacity: p, pad: 80, light: 0.5 }, (lg) => {
      kit.browser(lg, { x: 600, y: 370, w: 1200, h: 740, url: 'app.acme.com' }, (sc) =>
        lg.image('screens/dashboard.png', { x: sc.x + sc.w / 2, y: sc.y + sc.h / 2, w: sc.w, h: sc.h }))
    })
  },
  cues: (c) => [c.cue('whoosh', c.word('dashboard'), { align: 'peak', gain: -6 })],
})
```

### Rules (non-negotiable)

1. **Pure function of `f`.** No `Math.random()` (use `f.rand()`), no `Date.now()`, no timers, no module-level mutable state, no async work in `render`.
2. **No magic numbers for layout.** Use `f.stage` (`w, h, cx, cy, safe, title, portrait`) and `kit.responsive(f.stage).s` so the scene works in 16:9, 9:16 and 1:1.
3. **Positions are centers.** `x, y` of rects, images, layers, text are centers unless `anchor` / `align` say otherwise.
4. **Anchor to the voice, not to seconds,** whenever something relates to a spoken word: `f.in('phrase')`, `anim: { at: 'phrase' }`, `sync: 'voice'`, `f.word('x').end`. Numbers are local seconds since the scene start.
5. **Keep text inside `f.stage.title`** (title-safe). `mvs check` reports text leaving the frame.
6. **Brand tokens, not hex codes:** `fill: 'primary'`, `color: 'muted'`, `'gradient:brand'`, `style: 'h2'`, `radius: 'lg'`, `shadow: 'md'`.
7. Assets are referenced relative to `assets/` (`'screens/app.png'`, `'recordings/demo.mp4'`).

### The two objects

- **`f` (Frame):** `t` (timeline s), `lt` (local s), `p` (0..1), `dur`, `start`, `end`, `stage`, `brand`, `quality`, `audio.{level,pulse,beat}`, `transition.{phase,p}`; `at/local/since(anchor)`, `in(anchor, dur, ease)`, `out(dur)`, `enter()`, `exit()`, `show()`, `spring(anchor, cfg)`, `word/phrase/sentence/section(text)`, `has(text)`, `speaking()`, `rand(key)`, `wiggle(freq, amp)`, `warn(msg)`.
- **`g` (Graphics):** `fill`, `rect`, `circle`, `ellipse`, `arc`, `line`, `poly`, `path`, `text`, `measure`, `image`, `video`, `icon` (Lucide names), `group({x,y,scale,rotate,opacity,clip,blur})`, `layer({w,h,x,y,z,rotateX/Y/Z,scale,blur,blend,cache,pad,light,res,screen}, draw)`, `camera({x,y,z,zoom,rotate,focus,aperture})`, `plane(z, draw)`, `screen(draw)`, `fx({grade,bloom,…})`, `glow`, `color`, `gradient`, raw `ctx`.

Full reference: `docs/scene-api.md`. Components and templates: `docs/kit-and-templates.md`.

## 6. Audio

- Voiceover: `assets/audio/voiceover.wav` is used automatically; set `audio.voiceover: { src, offset }` in `project.ts` to start it later (offset = seconds of picture before the first word, 0.3–0.8 feels natural).
- Music: `audio.music: { src: '../../assets/music/ambient-pulse.ogg', gain: -18, duck: 9 }` or your own file. It ducks under the voice automatically.
- SFX: transitions add a whoosh by default. Add cues in a scene's `cues(c)` or in `project.ts → cues`. Library: `npx mvs sfx --list` (whoosh, whoosh-fast, whoosh-deep, swipe, reverse, riser, impact, hit, click, tap, pop, tick, ding, notify, type, glitch, shimmer). Use `align: 'peak'` for whooshes/risers. Less is more: SFX at −6…−12 dB, one per beat, not per element.
- The mix (`build/mix.wav`, −14 LUFS) is rebuilt automatically when inputs change.

## 7. Quality bar (what "professional" means here)

Read `docs/motion-guide.md` once. The essentials:

- **Hierarchy:** one primary element per beat; secondary elements follow 0.1–0.3 s later; never animate everything at once.
- **Easing:** entrances decelerate (`expoOut`, brand `enter`), exits accelerate and are faster, camera moves use `camera`/`smooth`. No linear motion except progress bars and scrolling.
- **Timing:** visuals lead the voice by ~0.1–0.2 s; hold text long enough to read (≥ 0.3 s per word on screen); cut in pauses (`cut()` does this).
- **Always alive:** subtle camera drift (`kit.drift`), parallax depth, ambient particles/light — but no constant busy motion.
- **Depth:** 3D layers with `light`, shadows (`shadow: 'lg'`), DOF/blur for background planes, glows for emphasis.
- **Typography:** use the type scale (`hero/h1/h2/h3/body/label/caption/eyebrow`), ≤ 2 type sizes per scene, ≤ 8 words per headline line, accent (`**word**`) for the key word only.
- **Transitions with intent:** `zoom` into a reveal, `slide/push` between related steps, `whip` for energy, `glitch` sparingly, `iris/fade` for endings, hard `cut` for punchy beats. Vary them; don't use the same one every time.
- **Contrast and safe areas:** text on busy backgrounds gets a panel or darker plane; keep text in title-safe.
- **Sound:** every major visual hit has a matching sound; the voice is always intelligible (ducking is automatic).

Before declaring a video done: `mvs check` clean, contact sheet reviewed, every transition still looked at, draft watched (or sampled frame by frame), final rendered.

## 8. Diagnosing problems

| Symptom | Do this |
| --- | --- |
| Anything fails | `npx mvs doctor` |
| Scene shows a red "crashed" banner | Exception in `render()`; message in `mvs check` output and the preview's warnings (`w`) |
| `phrase "…" not found in the voiceover timing` | The text is not in `script.md` / not spoken, or timing is stale → fix the text or run `mvs align` |
| `data/timing.json is stale` | `npx mvs align <id>` |
| Animations off after a new voiceover | `mvs align` + `mvs analyze`; check `cut()`/`section()` anchors with `mvs info` |
| Asset not found / placeholder box | Path relative to `assets/`; extension optional; run `mvs assets` for recordings |
| Recording frozen / not shown | `mvs assets <id> --force` (frames in `build/frames/`) |
| Render slow | `--draft`, `--scene x`, `--from/--to`, cache static layers (`cache: 'key'`), fewer blurred layers; `MVS_GL=gpu` on GPU machines |
| No audio in the video | Project has no voiceover/music/cues, or files missing → `mvs check`, `mvs mix <id>` |
| Browser not found | `npm run setup` or `MVS_BROWSER=/path/to/chrome` |
| Network, `EPERM`/read-only or Chromium launch errors in Codex's sandbox | Allow network for the sandbox (`network_access = true`) or approve running the command outside it — `docs/codex.md` |

More: `docs/troubleshooting.md`.
